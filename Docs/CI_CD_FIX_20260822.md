# Sửa lỗi CI/CD không chạy trên `Linh-dev-1`

## Nguyên nhân

Workflow `.github/workflows/ci.yml` trước đây chỉ có trigger push cho `main`, `master`, `develop` và pull request vào `main`, `master`. Nhánh phát triển hiện tại là `Linh-dev-1`, nên mỗi lần push lên nhánh này GitHub Actions không tạo run nào. Lịch sử GitHub chỉ có một run thành công trên nhánh `Linh-CI/CD`, không phải `Linh-dev-1`.

## Thay đổi

Workflow hiện đã chạy khi:

| Sự kiện | Branch |
|---|---|
| Push | `main`, `master`, `develop`, `Linh-dev-1` |
| Pull request | `main`, `master`, `develop`, `Linh-dev-1` |
| Chạy thủ công | `workflow_dispatch` |

Workflow cũng khai báo `permissions: contents: read` và dùng `npm ci` thay cho fallback `npm ci || npm install`, để lỗi dependency không bị che giấu.

## Các job hiện có

CI chạy song song build/test backend .NET 8 và build frontend Next.js. Backend restore, build Release và test `CloudService.Tests`; frontend cài dependency bằng `npm ci` rồi chạy `npm run build`.

## Docker development và deployment

Compose development (`docker-compose.yml`) build trực tiếp API, frontend và SQL Server, có healthcheck cho SQL Server, tự migrate trong môi trường demo và dùng volume `sqlserver_data`. Frontend có Dockerfile multi-stage dùng Next.js standalone, còn backend dùng Dockerfile multi-stage .NET 8.

CI job `docker-build` chạy `docker compose config` và `docker compose build` sau khi backend/frontend build và test thành công. Vì vậy pull request không chỉ kiểm tra source mà còn xác nhận các image Docker có thể build.

Workflow `.github/workflows/deploy.yml` build và push hai image lên GitHub Container Registry khi push vào `main`, `master` hoặc `Linh-dev-1`, hoặc khi chạy thủ công. Bước deploy server chỉ chạy khi repository variable `DEPLOY_ENABLED=true`; việc publish image không tự động đồng nghĩa với SSH deploy. Nó yêu cầu các GitHub Actions secrets sau:

| Secret/variable | Ý nghĩa |
|---|---|
| `DEPLOY_ENABLED` | Repository variable bật deployment tự động |
| `DEPLOY_HOST` | Host/IP máy chạy Docker |
| `DEPLOY_USER` | Tài khoản SSH |
| `DEPLOY_SSH_KEY` | Private key SSH tương ứng, không commit vào repository |
| `DEPLOY_PATH` | Thư mục triển khai trên server |
| `DEPLOY_PORT` | Cổng SSH, mặc định `22` |
| `MSSQL_SA_PASSWORD` | Mật khẩu SQL Server production |
| `JWT_SECRET` | Secret ký JWT production |

Trên server, workflow copy `docker-compose.production.yml`, pull image theo commit SHA, chạy `docker compose up -d --remove-orphans` và dọn image cũ. Compose production không dùng mật khẩu mặc định và tắt auto-migration theo mặc định. Người vận hành cần tạo file `.env` hoặc export các biến production trên server trước lần deploy đầu tiên.

Frontend đã được chuẩn hóa để gọi API và file upload qua đường dẫn relative `/api` và `/uploads`. Next.js proxy các đường dẫn này tới `API_PROXY_URL`, mặc định là API local ở development và `http://api:8080` trong Compose. Nhờ đó image production không còn phụ thuộc vào `localhost:5154` của máy người dùng.

Sandbox hiện không có Docker daemon, nên không thể chạy `docker compose build` cục bộ; việc xác nhận cuối cùng được thực hiện qua job `docker-build` trên GitHub Actions hoặc máy có Docker Desktop.
